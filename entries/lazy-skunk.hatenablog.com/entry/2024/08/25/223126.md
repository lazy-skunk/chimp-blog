<p>Python の例外の型注釈で「クラスを渡すのか、インスタンスを渡すのか」を区別する必要があったという話。</p>

<p><code>ValueError</code> は例外クラス。<code>ValueError("message")</code> のように作ったものがそのインスタンスになる。</p>

<h3>例外クラスを受け取る場合</h3>

<p><code>pytest.raises</code> に渡すため、<code>ValueError</code> というクラス自体を受け取りたいなら、次の型注釈になる。</p>

<pre><code>exception: type[ValueError] | None  # ValueError というクラス、または None</code></pre>

<p>一方、次の注釈は <code>ValueError</code> のインスタンスまたは <code>None</code> を表す。これ自体が誤った注釈なのではなく、受け取りたいものが違う。</p>

<pre><code>exception: ValueError | None  # ValueError のインスタンス、または None</code></pre>

<h3>テストでの使い方</h3>

<p>以下はテストコードの一部。<code>MyClass</code> や <code>_INVALID_VALUE</code> はテスト対象に合わせて定義しているもの。</p>

<pre><code>from unittest.mock import patch

import pytest


@pytest.mark.parametrize(
    &quot;argv, expected, exception, exception_message&quot;,
    [
        (
            [&quot;test.py&quot;, _INVALID_VALUE],
            None,
            ValueError,
            f&quot;Invalid value specified: {_INVALID_VALUE}.&quot;,
        ),
    ],
)
def test_something(
    argv: list[str],
    expected: str | None,
    exception: type[ValueError] | None,
    exception_message: str,
) -&gt; None:
    instance = MyClass()

    with patch(&quot;sys.argv&quot;, argv):
        if exception is not None:
            with pytest.raises(exception, match=exception_message):
                instance._private_method()
        else:
            assert instance._private_method() == expected</code></pre>

<p>パラメーターには <code>ValueError</code> を渡し、テスト内でそのクラスを <code>pytest.raises</code> に指定している。</p>

<p>クラスも Python のオブジェクトなので、「オブジェクトだから型ではない」という整理ではなかった。</p>
