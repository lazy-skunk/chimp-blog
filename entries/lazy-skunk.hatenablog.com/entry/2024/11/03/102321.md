<p><code>pytest.mark.parametrize</code> を使うたびに、テストデータをデコレーターの中へ直接書かなければいけないと思い込んでいた。</p>

<p>でも第2引数に渡すデータは先に変数として定義しておけばよかった。分かってしまえば、それだけの話なんだけど…。</p>

<h3>データを直接書く場合</h3>

<p>まずは今までの書き方。<code>MyClass</code> はテスト対象のクラスとして別に定義している。下のデータは配置の違いを示すための例。</p>

<pre><code>@pytest.mark.parametrize(
    &quot;size, values, expected_values&quot;,
    [
        ([3, [1, 10, 3, 5], [1.0, 5.5, 4.66667, 6.0]]),
        ([3, [1, 10, 3, 5], [1.0, 5.5, 4.66667, 6.0]]),
        ([3, [1, 10, 3, 5], [1.0, 5.5, 4.66667, 6.0]]),
    ],
)
def test_something(
    size: int, values: list[int], expected_values: list[float]
) -&gt; None:
    my_class_instance = MyClass(size)
    ROUND_DECIMALS = 5
    for value, expected_value in zip(values, expected_values):
        assert (
            round(my_class_instance.do_something(value), ROUND_DECIMALS)
            == expected_value
        )
</code></pre>

<p>同じデータを別のテスト関数でも使いたいとき、このリストをあちこちに書くと見通しが悪くなる。何よりダサい。</p>

<h3>データを変数へ切り出す</h3>

<p>データを先に定義すれば、デコレーターからはその変数を渡せる。</p>

<pre><code>_TEST_DATA = [
    ([3, [1, 10, 3, 5], [1.0, 5.5, 4.66667, 6.0]]),
    ([3, [1, 10, 3, 5], [1.0, 5.5, 4.66667, 6.0]]),
    ([3, [1, 10, 3, 5], [1.0, 5.5, 4.66667, 6.0]]),
]

@pytest.mark.parametrize(&quot;size, values, expected_values&quot;, _TEST_DATA)

def test_something(
    size: int, values: list[int], expected_values: list[float]
) -&gt; None:
    my_class_instance = MyClass(size)
    ROUND_DECIMALS = 5
    for value, expected_value in zip(values, expected_values):
        assert (
            round(my_class_instance.do_something(value), ROUND_DECIMALS)
            == expected_value
        )</code></pre>

<p>別のテストでも使うなら、同じデータを参照するように書けばよい。</p>

<pre><code>@pytest.mark.parametrize(&quot;size, values, expected_values&quot;, _TEST_DATA)</code></pre>

<p>ただし、内容が偶然似ているだけのテストまで、無理に同じデータへまとめる必要はない。変更するときも一緒に変わってほしいデータなのか？というところは考えないといけないな。</p>

<h3>変更されるデータを使い回す場合</h3>

<p>pytest はパラメーターの値をテストごとに自動でコピーしてくれるわけではない。リストなどをテスト対象の処理が書き換える場合は、他のテストへ影響を残さないようにしたい。</p>

<p>例えば入れ子のリストを使う場合は、テストの中でコピーを作ってから処理に渡せる。以下は別のテストの抜粋で、<code>_GRID_TEST_DATA</code> と <code>update_grid</code> は別に定義しているもの。</p>

<pre><code>import copy


@pytest.mark.parametrize(&quot;grid, expected&quot;, _GRID_TEST_DATA)
def test_update_grid(grid: list[list[int]], expected: list[list[int]]) -&gt; None:
    input_grid = copy.deepcopy(grid)
    update_grid(input_grid)
    assert input_grid == expected</code></pre>

<p>デコレーターの引数で一度だけ <code>deepcopy</code> しても、各テストの実行時に毎回コピーされるわけではない。コピーしたつもりでもどこで作るかが大事だった。</p>

<p>for 文で無駄を省けるようになったあの頃と、少し似た感覚がある。めちゃくちゃ恥ずかしいけど、「なんか冗長なんだよなあ」と感じること自体は大事にしたい。</p>
