<h3>作ったものを一覧で確認する</h3>

<p>いろいろ動かしてきたけど、作ったボリュームってどこで確認できるんだ？と思って調べたら、次のコマンドで確認できた。</p>

<pre><code>docker volume ls
docker network ls
docker image ls</code></pre>

<p>ボリュームだけでなく、ネットワークやイメージも同じような形で確認できる。</p>

<h3>-i と -t の役割</h3>

<pre><code>docker run -it --network todo-app nicolaka/netshoot</code></pre>

<p><code>-i</code> は <code>--interactive</code> の略で、標準入力を開いたままにする指定。<code>-t</code> は <code>--tty</code> の略で、疑似端末を割り当てる指定だった。</p>

<p><code>-i</code> だけでも入力は渡せるが、対話的なシェルを普段のターミナルに近い形で使いたいときは、<code>-it</code> と組み合わせることが多いらしい。<code>-t</code> は単に標準入力を接続するためだけの指定ではないのか。</p>

<p>パイプからデータを渡すなど、疑似端末を必要としない場面なら <code>-i</code> だけを使うこともありそう。自分が使う未来はまだ見えないけど、何かを自動化するときに出番があるんだろうなあ。</p>

<p>対話不要って遊戯王の先行制圧みたいだな。厳密には対話拒否だが。</p>

<h3>Compose でまとめて起動する</h3>

<p><code>docker compose up -d</code> を実行してみたら、なんと便利なことでしょう。設定した複数のコンテナが連携した状態で起動した。そういうコマンドだから当然なんだけど…。</p>
