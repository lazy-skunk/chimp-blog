<h3>ボリュームをマウントする</h3>

<pre><code>docker run -dp 127.0.0.1:3000:3000 --mount type=volume,src=todo-db,target=/etc/todos getting-started</code></pre>

<p><code>-dp</code> は前回の復習で、<code>--detach</code> と <code>--publish</code> をまとめたもの。バックグラウンドでの実行とポートの公開を指定している。</p>

<p>今回気になったのは <code>--mount</code>。<code>docker run --help</code> では、ファイルシステムのマウントをコンテナに接続するためのオプションとして説明されていた。</p>

<p>あえて説明を書くまでもないか…。オプションの文字どおりでマウントしますよって話。</p>

<ul>
<li><code>type=volume</code>：Docker が管理するボリュームを使う。</li>
<li><code>src=todo-db</code>：使うボリュームの名前。</li>
<li><code>target=/etc/todos</code>：コンテナ内のマウント先。</li>
</ul>

<p><code>--mount</code> の指定項目をコマンドで一覧できないかなと思ったけど、ヘルプには細かい説明がなかった。そこはドキュメントを確認するしかないか。</p>

<h3>バインドマウントとの違い</h3>

<p>Docker が管理する保存領域を使うのがボリュームマウント。ホスト上の特定のファイルやディレクトリーをコンテナに見せたい場合は、バインドマウントという選択肢もある。</p>

<p>ここで気づいたことだが、今のプロジェクトではボリュームマウントを使っているようだな。</p>
