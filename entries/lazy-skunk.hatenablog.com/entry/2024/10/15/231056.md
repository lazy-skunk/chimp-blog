<p>DOM 操作で <code>DocumentFragment</code> を使うと性能が上がる！と断言したかったが、調べていくうちに「場合による」くらいに落ち着いた話。</p>

<h3>DocumentFragment を使う例</h3>

<p>複数の要素を一度フラグメントへ追加し、最後にまとめてリストへ移す例と、直接リストへ追加する例を並べてみた。</p>

<pre><code>function createListWithFragment() {
  const fragment = document.createDocumentFragment();
  const list = document.createElement(&quot;ul&quot;);

  for (let i = 0; i &lt; 10; i++) {
    const listItem = document.createElement(&quot;li&quot;);
    listItem.textContent = `Item ${i + 1}`;
    fragment.appendChild(listItem);
  }

  list.appendChild(fragment);
  return list;
}

function createListWithoutFragment() {
  const list = document.createElement(&quot;ul&quot;);

  for (let i = 0; i &lt; 10; i++) {
    const listItem = document.createElement(&quot;li&quot;);
    listItem.textContent = `Item ${i + 1}`;
    list.appendChild(listItem);
  }

  return list;
}</code></pre>

<p><code>DocumentFragment</code> を使うと、途中の組み立てを一時的な入れ物にまとめられる。ただ、この例ではどちらの関数もページへ追加する前の <code>ul</code> を組み立てている。後者だけがループのたびにページを再描画しているという比較にはなっていない。</p>

<h3>必ず高速になるとは言えない</h3>

<p><a href="https://developer.mozilla.org/ja/docs/Web/API/DocumentFragment">MDN の説明</a>でも性能上の利点は過大に語られがちで、エンジンによっては遅くなる場合もあるとされている。差が小さいこともあり、使えば必ず高速化できるとは言えなさそうだ。</p>

<p>速くなるかどうかは実際の使い方に近い条件で測ってみないと分からないんだな。性能だけでなく、要素を組み立てるコードが読みやすくなるかどうかでも選べそう。</p>

<p>昔、運用保守案件で塩漬けになっていた頃、業務効率化のために VBA を書いていた。そのときの性能改善と似たような考え方かなあと思い出して、この記事を書きたくなった。</p>
