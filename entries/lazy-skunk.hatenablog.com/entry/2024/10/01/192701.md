<p>JavaScript の処理を分割したくて、PubSub パターンを試してみた。Publish と Subscribe、つまりイベントの発行と購読を使ってやり取りする考え方。</p>

<p>もともとは一つのファイルに関心のある処理を全部書いていた。次第に肥大化してきたので、主要な処理を担当する部分と画面を担当する部分に分けてみたが、今度はお互いを呼び合う形になってしまった。</p>

<h3>直接呼び合う代わりにイベントを使う</h3>

<p>MVC の考え方も調べてみたが、モデルの内部で起きた変化を画面へ伝えたいときに深いところまでやり取りする形になってなんだか歪だなあと感じた。</p>

<p>そこでモデルはイベントを発行し、画面の更新を担当する側がそのイベントを購読する形にしてみる。</p>

<p>コードはこんな感じ。仕組みを追いやすいよう、一つのイベントに登録できるコールバックは一つだけにしている。</p>

<pre><code>export class PubSub {
  #subscribers = new Map();

  subscribe(event, callback) {
    this.#subscribers.set(event, callback);
  }

  publish(event, data) {
    const callback = this.#subscribers.get(event);
    if (callback) {
      callback(data);
    }
  }
}</code></pre>

<p>モデルは処理を終えたら変更後の状態をイベントとして渡す。画面のオブジェクトを直接持つ必要はない。</p>

<pre><code>export class Model {
  #pubsub;
  #value = 0;

  constructor(pubsub) {
    this.#pubsub = pubsub;
  }

  update(value) {
    this.#value = value;
    this.#pubsub.publish(&quot;state-changed&quot;, { value: this.#value });
  }
}</code></pre>

<p>コントローラーがイベントを購読し、受け取った状態を画面へ渡す。</p>

<pre><code>export class Controller {
  #model;

  constructor(model, ui, pubsub) {
    this.#model = model;
    pubsub.subscribe(&quot;state-changed&quot;, (state) =&gt; ui.render(state));
  }

  update(value) {
    this.#model.update(value);
  }
}</code></pre>

<p>使う側では同じ PubSub のインスタンスをモデルとコントローラーへ渡す。</p>

<pre><code>const pubsub = new PubSub();
const model = new Model(pubsub);
const ui = { render: (state) =&gt; console.log(state) };
const controller = new Controller(model, ui, pubsub);

controller.update(1);</code></pre>

<h3>依存がなくなるわけではない</h3>

<p>モデルから画面の具体的なメソッドを呼ばずに済むようになるが、イベント名と渡すデータの形は両者で合わせておく必要がある。何でも PubSub にすればいいってわけでもないのか。</p>

<p>今までの案件では一つのファイルに数千行書いてあるのが当たり前だったので、こういうやり方があることを知らなかった。</p>

<p>今まで見てきた現場のコードにも、もう少し整理できるところはあったんじゃないかなあ。</p>

<p>コールバック関数って名前は聞いたことがあったけど、どういうものか知らなかったな…。</p>
