<p>知っている人には当たり前かもしれないけど、属性名を文字列で指定できる <code>getattr</code> が便利だったという話。</p>

<h3>属性ごとの分岐をまとめる</h3>

<p>まずはクラス内のメソッドの例。<code>getattr</code> を使わず、引数に応じて属性を返すと、こんな書き方になる。</p>

<pre><code>    def get_something(self, keyword: str) -&gt; float:
        if keyword == &quot;A&quot;:
            return self.a
        elif keyword == &quot;B&quot;:
            return self.b
        elif keyword == &quot;C&quot;:
            return self.c
        elif keyword == &quot;D&quot;:
            return self.d
        else:
            raise ValueError(f&quot;Unknown keyword: {keyword}&quot;)
</code></pre>

<p>属性名の規則がそろっていれば、次のようにも書ける。</p>

<pre><code>    def get_something(self, keyword: str) -&gt; float:
        if keyword not in [&quot;A&quot;, &quot;B&quot;, &quot;C&quot;, &quot;D&quot;]:
            raise ValueError(f&quot;Unknown keyword: {keyword}&quot;)

        return getattr(self, keyword.lower())</code></pre>

<p>うーん、この例だとあのときの感動をあまり伝えられていないかもしれない…。</p>

<p><code>getattr(self, keyword.lower())</code> で文字列に対応する属性を取得できる。この例では受け付ける名前を先に確認している。</p>

<p>元の分岐も悪くないと思うし、短ければ何でもいいってわけではない。でもこういう書き方も選べるようにはしておきたいな。</p>

<h3>同じ計算を属性だけ変えて使う</h3>

<p>便利だと感じたのは栄養素を計算していたとき。次のコードはその一部。</p>

<pre><code>        return sum(
            getattr(food_information, nutrient_property)
            * food_information.grams_per_unit
            * self.food_intake_variables[food_name].varValue
            / self._GRAM_CALCULATION_FACTOR
            for food_name, food_information in zip(
                self.food_intake_variables.keys(), self.food_information
            )
        )</code></pre>

<p><code>nutrient_property</code> には熱量、たんぱく質、脂質、炭水化物に対応する属性名が入る想定。</p>

<p><code>getattr</code> を使う前は、その属性だけを変えた同じような計算式が4つあり、画面を埋め尽くしていた。属性以外は同じなのにうまくまとめられないのかなと思っていたらできるんだな。</p>

<p>for 文を使わず、同じ処理をずらずら並べるのに似ていて、あの状態はなかなかの地獄だった。</p>
