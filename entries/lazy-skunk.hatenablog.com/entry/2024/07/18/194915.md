<p>待機機で InfluxDB の CLI を使おうとしたら、いつの間にか認証が通らなくなっていた。</p>

<pre><code>401 Unauthorized: unauthorized access InfluxDB CLI</code></pre>

<p><code>influx auth list</code> も <code>influx bucket list</code> も実行できず、しばらくハマった。</p>

<h3>稼働機のファイルを反映していた</h3>

<p>エラー自体は認証失敗を示しているが、なぜ急に起きたのかが分からなかった。</p>

<p>振り返ると、稼働機のファイルを待機機へ反映していた。それに伴ってサーバー側のトークン情報も変わり、CLI で使っていた設定と合わなくなったのではないかという見立て。</p>

<p>そりゃあ認証エラーになるよね…と思ったものの、最初からそこに気づけるわけではないんだよなあ。</p>

<h3>待機機で行った作業</h3>

<p>まず、自分の環境で使っていた <code>/etc/influxdb2/configs</code> を次の内容で作成した。ここに書いているトークンや組織名は実際の値ではなく、設定内容を示すためのもの。</p>

<pre><code>[default]
  url = &quot;http://localhost:8086&quot;
  token = &quot;稼働機のトークン&quot;
  org = &quot;任意の組織名&quot;
  bucket = &quot;任意のバケツ名&quot;</code></pre>

<p>続いて CLI の設定を作成した。</p>

<pre><code>influx config create -a -n default -u http://localhost:8086 -o 組織名 -t 稼働機のトークン</code></pre>

<h3>まだ切り分けられていないこと</h3>

<p>この二つを行ってから動作確認したので、片方だけでもよかったのかもしれない。まとめてやってから確認したので、そこは分からないんだよなあ。</p>

<p>設定ファイルの場所も CLI の起動方法や環境に依存する。ひとまず自分の環境では復旧したけど、この二つをセットでやれば必ず直るとは言えなさそう。</p>
