<p>mock を使うとき <code>autospec=True</code> を指定しておくと引数の渡し間違いなどに気づきやすくなる。</p>

<p>使える属性や引数の形を元のオブジェクトに合わせてくれるらしい。ただし、本物と同じ処理までしてくれるわけではない。</p>

<h3>引数の数を間違えた場合</h3>

<p>例えば次のようなクラスがあるとする。</p>

<pre><code>class Calculator:
    def add(self, num1: int, num2: int) -&gt; int:
        return num1 + num2</code></pre>

<p>次は <code>autospec</code> の有無を比べるための例。<code>add</code> の計算結果を検証するテストではないので、そこは勘弁してほしい。</p>

<pre><code>from unittest import mock


def test_add() -&gt; None:
    with mock.patch.object(Calculator, &quot;add&quot;, autospec=True):
        test_instance = Calculator()
        test_instance.add(1, 2)


def test_add2() -&gt; None:
    with mock.patch.object(Calculator, &quot;add&quot;):
        test_instance = Calculator()
        test_instance.add(1, 2, 3)</code></pre>

<p><code>test_add</code> は <code>autospec=True</code> を指定し、引数も正しく渡しているので、呼び出し時のエラーは発生しない。</p>

<p>一方、<code>test_add2</code> は引数を一つ多く渡している。本来のメソッドならエラーになるのに、制約のない mock に置き換えているため、その呼び出しを受け入れてしまう。結果としてこのテストは成功してしまう。いけませんね。</p>

<p>この例でも <code>autospec=True</code> を指定すれば、引数が多いことを検知して <code>TypeError</code> になる。</p>

<h3>何を模倣しているのか</h3>

<p>ここで確認できるのは主にオブジェクトのインターフェース。mock に置き換えた <code>add</code> が本物と同じように足し算をするわけではない。戻り値や副作用が必要なら、それぞれ設定することになる。</p>

<p>型ヒントや静的解析で気づける間違いもあるけれど、テストでも元の呼び出し方に近い制約を保てるのはありがたい。mock を使うときに使っておきたい指定だなあと思った。</p>
