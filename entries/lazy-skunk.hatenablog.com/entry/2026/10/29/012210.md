## ローカルで記事を書きたかった

はてなブログの記事をローカルで書きたい。書いたものを CD でブログに反映できたらいいなと思って調べたらできるらしい。

それなら投稿する頻度も上がるのではないか？ということで GitHub と連携することにした。

動作確認も兼ねて、公開までの流れを記録しておく。

## 最初の設定

はてなの「HatenaBlog Workflows Boilerplate」からリポジトリーを作って clone した。`blogsync.yaml` にはブログのドメインとはてな ID を設定した。

ブログのドメインは `lazy-skunk` なのに、はてな ID は `lazy_skunk`。何も考えずに `username` もハイフンにしたら、`initialize` で `401 Invalid login`。そりゃログインできないか。

GitHub 側では Actions の変数 `BLOG_DOMAIN` に `lazy-skunk.hatenablog.com`、Secret `OWNER_API_KEY` にはてなブログの API キーを登録した。API キーはアカウント設定で確認する。あとは Actions の書き込み権限と PR 作成権限も設定。設定画面を行ったり来たり。

`initialize` をもう一度実行して、今度は既存の記事を取得できた。

## 記事を書くとき

最初はローカルで Markdown ファイルを作ればいいと思っていた。ただ、取り込んだ公開記事のファイルを見ると、名前や置き場所に規則性がある。勝手に作るだけでは済まないんだろうなと薄々思っていたら、やっぱり違った。このテンプレートでは、先に GitHub の Actions から `create draft` を実行してタイトルを入れる。はてなブログに下書きができて、`draft_entries` に記事ファイルを追加する PR もできる。

できた PR のブランチに切り替えて、今この文章をローカルで書いている。ここまではできた。次はコミットして push し、PR とブログ側の下書きに反映されるか見てみる。

## 下書きを push してみた

PR にはプレビューへのリンクがあり、そこから下書きの表示を確認できた。ローカルで書いて、そのまま見た目も確認できるのは良さそう。

## 次は公開してみる

下書きの反映は確認できた。公開までちゃんと動くのか見てみる。

記事ファイルの `Draft: true` は消した。あとは push して、ドラフト PR を Ready for review にしてからマージするらしい。無事に公開できれば、ローカルで書いて GitHub 経由で投稿する流れはひと通り確認できたことになる。

今の時代にこんなことをする意味があるのかはまじで分からんけど、とりあえずやってみるかあ。
